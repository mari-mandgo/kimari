作成日: 2026年8月13日

「実際に人に使ってもらう」までに何をどの順でやるか。
やること自体の一覧は `docs/todo.md` のB。**こちらは順番と理由**を書く。

料金は `docs/pricing-plan.md`、原価の実測は `docs/benchmark.md`。

## 1. 置き方は2つある

音声を外に出さない設計なので、置き場所の選択肢が普通のWebアプリより狭い。

| | 置き方 | 向く相手 |
|---|---|---|
| **A. SaaS** | こちらが用意した1台に全社分を載せ、ログインして使ってもらう | 中小の工務店・リノベ会社。導入が5分で済む |
| **B. 設置型** | その会社の事務所のPCやNASに丸ごと置く | 個人情報の外部保管を嫌う会社、ゼネコン系 |

**Aで始める。** Bは「音声を外に出さない」を極限までやりたい会社向けの上位プランとして、
あとから出す。中身は同じなので、Aが動けばBはほぼ設置作業だけになる。

### Vercelには載せられない

理由は2つ。どちらも設計の根っこに関わるので、回避ではなく前提として扱う。

- 現場データを `data/` にJSONで書いている。Vercelは書き込めない
- faster-whisper（Python）が同じサーバーに要る。Vercelに置けない

**VPS 1台に全部載せる。** さくら / ConoHa / Xserver あたりで月3,000〜5,000円。
Next.jsとPythonをDockerで1セットにする。

「Next.jsだけVercel、文字起こしは別サーバー」も技術的には可能だが、
**音声がVercelを経由する。** 製品の主張と食い違うので採らない。

## 2. やる順番

### ① データの置き場所 ← 作業量の半分

いま `data/*.json` に全部入っている。VPSならファイルのままでも動くが、
**バックアップと同時書き込みで必ず事故る。**

- PostgreSQL へ移す。ただし**構造は変えない**。いまのJSONをそのまま `jsonb` の1カラムに入れる
- 差し替えるのは `lib/store.ts` の中身だけ。呼んでいる側は触らない
- 写真・図面は S3互換ストレージ（Cloudflare R2 など）へ
- **録音だけはサーバー内に留める**（外部ストレージへ出した時点で主張が崩れる）

スキーマをきれいに設計し直したくなるが、**しない。**
いま動いているものを載せ替えるのが目的で、設計のやり直しではない。

### ② 文字起こしの詰まり ← 見落としやすい

faster-whisper をCPUで回すと、8分の音声に数分かかる。
**3人が同時に録音を上げたら順番待ちで固まる。**

- ジョブキューを入れて、同時実行数をCPUコア数で縛る
- 画面に「順番待ち3件目」と出す（黙って待たせない）
- 台数を増やすより、GPU付きVPS 1台のほうが安上がりになる可能性が高い。**要試算**

**リリース前に必ず実測する。**
ここは「使ってみたら遅すぎた」で信用を落とす種類の問題で、あとから直しても取り返せない。

### ③ 安全まわり

`docs/todo.md` B-2 と同じ。

```
・Cookie を secure: true へ戻す
  app/api/auth/route.ts と app/api/auth/form/route.ts
・共有リンクの有効期限と失効（いまは発行したら永久に開ける）
・アップロード容量の上限（顔写真は縮めているが、資料・図面は無制限）
・録音の保管期間を決めて、自動削除を入れる
```

### ④ 法務 ← コードより先に効いてくる

打ち合わせ録音には**施主の氏名・住所・電話**がそのまま入る。
工務店は施主から預かった個人情報をKIMARIに預けることになるので、
これは**個人情報の取扱いの委託**にあたる。

- 利用規約
- プライバシーポリシー
- **個人情報取扱いの委託契約のひな型**
- 有料にするなら特定商取引法の表示

**ひな型が無いと、まともな会社は導入できない。**
営業先の総務で必ず聞かれる。逆に、持って行けるだけで他のツールより信用される。

### ⑤ 知らせる仕組み

いまはKIMARIを開かないと気づけない。
施主には「担当者に届きました」と出るので、**放置されたように見える。**

Resendの無料枠（月3,000通）で足りる。

- 施主から相談が届いた → 現場を作った人へ
- 期限が近い・過ぎた → 担当者へ

### ⑥ 課金

Stripe。`docs/pricing-plan.md` の設計をそのまま使う。

**LLM原価は1件0.42円なので無視できる。**
効いてくるのはサーバー代だけなので、席数課金でも現場数課金でも成立する。

## 4. 進め方

全部を作り込んでから売らない。**1社に無料で入れて実運用に晒す。**

| | やること | 目安 |
|---|---|---|
| 1 | VPS 1台 + PostgreSQL で立てる（①②） | 1〜2週間 |
| 2 | 安全まわりと規約を揃える（③④） | 数日 |
| 3 | **知り合いの工務店1社に無料で入れて、3か月使ってもらう** | 3か月 |
| 4 | そこで出た不満だけ直す | |
| 5 | 通知と課金を足す（⑤⑥） | 1週間 |

`docs/todo.md` の **B-3（打ち合わせの編集・見積書の管理・会社の管理）は、3で必ず要求される。**
先に作るより、言われてから作るほうが正確なものになる。
いま想像で作ると、使われない機能になる可能性が高い。

## 5. 決めていないこと

- **GPUを使うか。** 文字起こしの実測を取ってから決める（②）
- **録音を残すか。** いまは文字起こし後に削除している。
  「言った言わない」の証拠として残したい要望は必ず出るが、
  残すなら保管期間・削除・開示の仕組みが要る。**残さない方針で始める**のが安全
- **設置型（B）の売り方。** 導入費 + 保守か、年額か
- IT導入補助金の支援事業者登録（ANDPAD等は登録済み。中小への販売力が上がる）
