# 最終プレゼン 大枠（Codexへの依頼書）

対象: AI HACK 2026 最終発表（上位8チーム）。**4分＋質疑3分**、東京カルチャーカルチャー。
作るもの: 8枚のスライド。**デザインは任せます。中身と順番と時間配分は動かさないでください。**

動く叩き台が `docs/pitch/pitch.html` にあります（矢印キーで進む／Fでフルスクリーン）。
中身はそのまま使えます。**見た目だけ作り直してください。**

---

## 大前提

- **4分は短い。** 日本語で1,200〜1,400字しか話せません。1枚に文は3行まで
- **会場の後ろの席から読めること。** 本文は最低24px相当。数字は特大
- **読ませない。** スライドは話の支えで、原稿ではありません
- 審査は8項目×5点。**どのスライドがどの項目に効くかを下に書いてあります。そこを弱めないでください**

## 各スライドの中身と台本

### 1. 表紙（15秒）

```
KIMARI（ロゴ）
話すだけで、現場が決まる。
打ち合わせの会話から、追加見積が必要な変更だけを見つける
AI HACK 2026 ／ Mari（金子麻里）／ 建築設計・施工管理 20年
```

> KIMARI、まりです。建築の設計と施工管理を20年やってきました。
> 打ち合わせの会話から、追加見積が必要な変更だけを見つけるAIエージェントを作りました。

**デザイン注意**: 叩き台ではロゴが濃紺の背景に埋もれています。白抜きのロゴを使うか、背景を明るくしてください。

### 2. 2つの発言（35秒）

左右2枚のカード。左=オレンジ、右=緑。

```
見出し：お金が動く変更に、双方が気づいていないことです。
小見出し：現場でいちばん揉めるのは、記録が無いことではありません

左（オレンジ）
「キッチン、60センチ寄せられないかな」
給排水の移設が発生します。床下の配管をやり直します。
→ 追加見積が必要

右（緑）
「建具の色、オークにしたい」
同一グレード内の色違いです。金額は変わりません。
→ 金額の変更なし
```

> 現場でいちばん揉めるのは、記録が無いことではありません。
> お金が動く変更に、双方が気づいていないことです。
> 「キッチンを60センチ寄せたい」。施主にとっては少し動かすだけですが、給排水の移設が発生します。
> 一方で「建具の色をオークに」は、同じグレードの色違いなので金額は変わりません。

### 3. 線引きが本体（25秒）

```
見出し：どちらも「変更」です。汎用のAIは、同じ欄に並べます。

強調枠：
建設業では、変更が出たら書面での見積提示が建設業法で義務づけられています。
この線引きが、このプロダクトの本体です。

文字起こしでも要約でもなく、
会話を、次に必要な行動へ変えることを作りました。
```

> どちらも会話の上では「変更」です。汎用の議事録AIは、この2つを同じ欄に並べます。
> 建設業では、変更が出たら書面での見積提示が法律で義務づけられています。
> **この線引きが、このプロダクトの本体です。**

### 4. デモ（45秒）— いちばん長く取る

**画面を実際に見せるか、デモ動画の抜粋を流します。**静止画で済ませないでください。

- 実演する場合: `https://kimari.vercel.app/demo` →「打ち合わせ」→「この打ち合わせを仕分けた結果を見る」
  （保存済みの結果が出るので待ち時間ゼロ。**会場のWi-Fiが不安なら、事前に開いておく**）
- 動画の場合: `https://youtu.be/6HwpSwbsNXw` の 0:40〜1:25 あたり

> 実際に動かします。8分の打ち合わせを録音して、仕分けたところです。
> 追加見積が必要な変更が3件。金額の変わらない決定、保留と期限、
> そして「言った言わない」になりそうな箇所まで分かれています。
> 施主にはこのページが自動で積み上がります。ログインは要りません。

### 5. 工程で変わる（40秒）— ここが山場

```
見出し：同じ発言でも、工程で出力が変わります。
小見出し：ここが、実務者にしか作れなかった部分です

左：見積提出（契約前）  16項目 ／ 51秒
右：解体確認（契約後）   3項目 ／ 32秒   ← 強調

強調枠：
契約後は、当初見積書（Excel）から読んだ契約64項目と突き合わせ、
その変更がなければ発生しなかった分だけを出します。外した項目も理由つきで返します。
```

> 開発中、AIは同じ発言から33項目を出してきました。整然と並んでいて、よくできて見えました。
> でも私は使えないと思いました。この打ち合わせは解体が終わったあとだったからです。
> 解体も撤去も、もう契約に入っています。
> いまは工程を判定して、契約前なら16項目、解体後なら3項目。**同じ入力で出力が変わります。**
> 根拠は一般常識ではなく、その現場の当初見積書64項目です。

### 6. 音声を外に出さない（25秒）

箇条書き3つ。

```
見出し：音声を、外に出しません。

・録音には施主の氏名・住所・電話がそのまま入ります
  文字起こしは自社のサーバーの中だけ。外部の文字起こしサービスへ送りません
・ルーターへ出るのは、個人情報を伏せたテキストだけ
  伏せ漏れがないかを毎回検証しています
・ブラウザ内蔵の音声認識は、機能ごと削除しました
  音声がGoogleへ送られるため、この説明と両立しないからです
```

> 打ち合わせの録音には、施主の氏名も住所も電話番号もそのまま入っています。
> 文字起こしは自社のサーバーの中だけで行い、外へ出るのは個人情報を伏せたテキストだけです。
> 途中まで、ブラウザ内蔵の音声認識も入れていました。便利ですが、音声がGoogleへ送られます。
> 説明と両立しないので、**機能ごと削除しました。**

**この節は構成図（`architecture.png`）を使ってもいい**ですが、4分では文字が読めません。
使うなら黒枠と青枠だけを抜き出した簡略版にしてください。

### 7. 原価（20秒）

数字3つを大きく。

```
見出し：1件、0.42円。
小見出し：LLM COST ／ すべて実測値です

0.42円   打ち合わせ1件（仕分け＋3文書＋翻訳）
270分の1  最上位モデル直指定 35.2円 → 0.13円
0円      文字起こし（自社サーバーで処理）

強調枠：
OrcaRouterで、定型の仕分けは安いモデル、含みのある会話だけ高いモデルに振り分け。
実際に使われたモデルを毎回記録しているので、原価を推定ではなく実測で言えます。
```

> 原価はすべて実測です。打ち合わせ1件で0.42円。
> 最上位モデルを直接指定すると35円かかるので、**約270分の1**です。
> それでも、追加見積が必要な3件の判定は全モードで一致しました。

### 8. 誰が払うか／これから（25秒）

```
見出し：記録を作る人が払い、読む人は無料です。

・困っているのは、あとから追加請求を説明する側（設計・工務店）
  一人親方 月1,980円／工務店 月9,800円。原価は月30件で12.6円
・職人が現場で録って送る経路は、無料のまま
  施主が職人へ直接言う一言が、最も揉めます。ここを塞ぐのが本体です
・本物の現場では、まだ運用していません
  数字はすべて、実際の録音と実際の見積書で測ったものです
```

> 課金は、記録を作る側だけです。職人と施主は無料にしました。
> 現場で施主が職人へ直接言う一言が、いちばん揉めます。
> そこを塞ぐのが本体なので、職人に課金して使われなくなったら意味がありません。
> 最後に正直に言います。**本物の現場では、まだ運用していません。**
> ただし数字はすべて、実際の録音と実際の見積書で測ったものです。
> 話すだけで、現場が決まる。KIMARIです。

## デザインの指示（Codexへ）

- **LPと同じ世界観**にしてください。`app/lp/page.module.css` の色とタイポを土台に
- 16:9（1280×720基準）。**キーボードで進む**こと（→ / スペース）
- **画像は `docs/pitch/` にあります**: `logo.png` `architecture.png` `owner.png`
- 依存を足さないこと。**1ファイルで完結**させてください（会場でネットが無くても開ける）
- アニメーションは控えめに。**切り替えで待たされるのが一番困ります**
- ロゴが暗い背景で沈んでいます。白抜きにするか、背景を変えてください

## やらないこと

- **文字を増やさない。** 台本にある言葉はスライドに全部載せないでください
- **数字を変えない。** 0.42円 / 270分の1 / 16→3 / 64項目 はすべて実測です
- **「本番導入済み」と読める表現にしない。** まだ運用していません
